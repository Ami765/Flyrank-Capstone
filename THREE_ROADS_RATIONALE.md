# Week 4 Assignment: Three Roads — Choose Your Stack

## 1. Project Constraints & Profile Profile Map
- **Budget Constraint:** 100% Free tools only.
- **Honest Skill Level:** Beginner learning React, TypeScript, and modern AI endpoint integrations.
- **Portfolio Functional Mapping:** Needs a landing view, an assignment asset matrix table, an interactive accessibility playground layout, and a real-time server health logger path.
- **Proof Display Style:** Code snippets, architectural schema boards, and a live interactive chatbot window module.
- **Dynamic Requirement:** Yes, the application must handle real-time asynchronous streaming conversation tokens server-side.

---

## 2. Three Roads Evaluation Matrix

### Road A: No-Code Drag and Drop (Carrd / Framer)
- **How to Build/Host:** Visual canvas workspace deployed instantly to Carrd/Framer free subdomains.
- **Backend Needed:** No.
- **Work Display Suitability:** Exceptional for fast image galleries, but completely incapable of handling deep dynamic server routing tasks or code-level API data streams.
- **The Core Trade-off:** Maximum visual speed but absolute zero custom logic control or private environment key security mapping framework.

### Road B: Plain Static Code (Vanilla HTML + CSS + JS)
- **How to Build/Host:** Written directly using a plain text editor and dropped onto Netlify Drag-and-Drop hosting.
- **Backend Needed:** Not natively, would require independent third-party widget configurations.
- **Work Display Suitability:** Good for standard layout paragraphs and embedded repository links, but lacks structure for complex state management variables.
- **The Core Trade-off:** Lightweight and free forever, but scales poorly. Managing asynchronous text tokens or isolated state parameters in vanilla script blocks becomes highly cluttered for a beginner.

### Road C: Unified Modern Framework (Next.js + Tailwind CSS)
- **How to Build/Host:** Structured React component subfolders written with TypeScript compilation, hosted 100% free on Vercel.
- **Backend Needed:** Yes, leverages server-side Edge Route handlers to proxy streaming requests securely without database weight.
- **Work Display Suitability:** Perfect. It displays code proofs cleanly, mounts interactive elements safely, and isolates private API authorization key tokens.
- **The Core Trade-off:** Steeper initial framework configuration learning curve, but delivers infinite maintainability and production-grade stability.

---

## 3. Pressure Test & Final Decision Rationale

- **What breaks if I pick the simplest (Road A)?** The application completely breaks. No-code platforms cannot connect to Vercel AI SDK route hooks or securely use a server-side `GOOGLE_GENERATIVE_AI_API_KEY` token stream.
- **What do I maintain if I pick the most powerful (Road C)?** I maintain an empty-cache project structure with explicit type configurations and simple utility-first Tailwind classes.

### Final Choice: Next.js + Tailwind CSS on Vercel
I chose **Next.js on Vercel** because it is the only stack that satisfies my structural need for a live, streaming AI chatbot module while keeping my private credentials entirely hidden on the server side. I did not choose Carrd or Vanilla HTML because they lack the secure server environments required to run live API connections without exposing private developer keys to public client scripts. 

This framework is highly maintainable for me because its modular layout tree allows me to fix sub-routes independently without breaking the global website application canvas. It displays my technical evidence with absolute clarity.
